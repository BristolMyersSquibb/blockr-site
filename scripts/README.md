# Generated tutorial media

Screenshots and video clips for the learn tutorials are generated by
scripts, not captured by hand. When the app UI changes, rerun the script
and the media is current again. No hand-drawn annotations; whatever needs
pointing out is said in the tutorial text next to the image.

## Tutorial page template

Each medium has one job. The video shows the flow once; the text is a
numbered action list with the exact labels to click and type; screenshots
are checkpoints only (either "your screen should look like this now" or a
gesture that is hard to read in motion). Page shape:

1. One sentence: what you build, then an image of the **final result**
   (payoff first, never the blank canvas).
2. The video (burned-in captions, poster frame set).
3. "Do it yourself": numbered steps, 2-3 checkpoint images inline.
4. A closing observation worth remembering (e.g. reactivity), then a
   "Next" link to the following tutorial.

## How to regenerate

One story script per tutorial in `scripts/demo-video/`, built on the same
recorder as the landing loop (see below), with the board helpers in
`story-lib.cjs`. The tutorials are recorded on the one-line install, so the
media show what a reader gets after `pak::pak("BristolMyersSquibb/blockr@dev")`.
Each take gives the video and the stills; the poster is the result still at
1152 px.

```bash
cd scripts/demo-video

# tutorials 1, 3, 4: an empty board from blockr::run_app()
Rscript -e 'options(shiny.port = 4010); blockr::run_app()' &
node story-tutorial-01.cjs tut01 http://127.0.0.1:4010/   # writes tut01-frames/, tut01-events.json, tut01-stills/

# tutorial 2 starts from the board after its step 1
Rscript tutorial-02-app.R 4320 &
node story-tutorial-02.cjs tut02 http://127.0.0.1:4320/

# video, same settings for every tutorial
node render.cjs tut01 tut01-video --speed 1.25 --captions --width 1728
ffmpeg -i tut01-video.mp4 -c:v libvpx-vp9 -b:v 0 -crf 36 -an tut01-video.webm
```

Use a port of 4000 or above on the Mac.

Then copy `tutNN-video.webm` to `public/videos/tutorial-NN.webm`, the stills to
`learn/`, and the result still (scaled to 1152 px) to
`public/videos/tutorial-NN-poster.png`. Look at the stills and a contact sheet
of the video first. The Reactivity page reuses the result stills of tutorials 1
and 2 as `docs/concepts/01-img-pipeline.png` and `01-img-dashboard.png`.

## How the scripts work

The techniques, so the next script doesn't rediscover them:

- **Captions in post.** The stories log captions with `S.caption()`;
  `render.cjs` draws them, so the stills taken during the take have none.
- **DAG canvas.** `run_app()` puts the Workflow canvas in a rail on the
  left; block panels fill the rest. Node positions come from the g6 graph:
  `HTMLWidgets.find('#' + el.id).getWidget()`, then `getNodeData()`,
  `getElementRenderBounds(id)`, `getViewportByCanvas()`, plus the offset of
  ShinyProxy's `iframe#shinyframe` when there is one. Output port = bottom
  centre, input port = top centre. Append straight down: the canvas is
  narrow, and a node drifting left ends up under the canvas toolbar.
- **Append and connect.** Drag from a node's output port into empty canvas:
  the `Append to <block>` menu opens and the new block arrives connected.
  Drop on another node's input port to connect two blocks.
- **Add menu.** Right-click > "Add block", type into
  `.blockr-menu__filter-input`, click the `.blockr-menu__item` whose
  `.blockr-menu__label` matches exactly (searching "ggplot" also matches the
  package name of the Facet block).
- **blockr.ui selects**: `.blockr-select__control`, then
  `.blockr-select__option`. The filter's value picker is
  `.blockr-select--multi`. The dataset picker is a selectize: click
  `.selectize-input`, then the `.selectize-dropdown .option`; typing does not
  filter it.
- **Dock tabs.** Dragging a tab onto the right part of a panel splits it;
  releasing at the window edge pins the panel into a narrow rail instead.
- **Block menu.** The controls toggle is "Controls" in the block's "…" menu
  (`.blockr-block-menu-btn`); the eye (`button[aria-label="Preview"]`)
  toggles the preview. Block content is rendered outside its dock group, so
  `story-lib.cjs` finds a block's eye by position.
- **Charts** (blockr.viz) are echarts canvases: click bars by position
  (`barAt()` in `story-lib.cjs`). Their settings sit behind the gear
  (`.blockr-gear-btn`); the selects are `.vz-row[data-role=category|func|value]`,
  the sections (Data, Interaction, ...) are `.blockr-tray-nav__group`.
- **Screencast size.** Headless Chrome's window is 1280x720 unless
  `--window-size` says otherwise, and the screencast crops a taller viewport
  to it. `film.cjs` sets the window to the viewport.

## Landing page loop

`public/videos/hero-build*` (the loop under the hero, `demo:` in
`index.md`) is recorded on an empty `run_app()` board from the one-line
install, light and dark:

```bash
cd scripts/demo-video
Rscript hero-loop-app.R 4190 &          # light
Rscript hero-loop-app.R 4191 dark &     # dark
node story-hero.cjs hero http://127.0.0.1:4190/
node story-hero.cjs hero-dark http://127.0.0.1:4191/
node render.cjs hero hero-build --speed 1.8 --width 1728 --zoom
node render.cjs hero-dark hero-build-dark --speed 1.8 --width 1728 --zoom
ffmpeg -i hero-build.mp4 -c:v libvpx-vp9 -b:v 0 -crf 38 -an hero-build.webm
```

`--zoom` only applies the close-up on the generated code at the end. The
chapters are logged as captions: their times in `<take>-events.json`
divided by the speed are the chapter starts in `index.md` (`chapters` for
light, `dark.times` for dark). Posters are a frame at the end of "Change it",
scaled to 1440 px.

## Demo loops (Examples page)

`public/videos/landing-build.*` (landing page) and
`public/videos/clinical-explorer.*` (the Clinical Explorer card on the
Examples page, set by `video:` in the gallery manifest) come from
`scripts/demo-video/`, recorded against the live apps on blockr.cloud. Needs
Google Chrome (or `CHROME_PATH=/usr/bin/chromium`) and ffmpeg with libx264
and libvpx.

```bash
cd scripts/demo-video
CALM="--zoom --captions --zscale 0.6 --tau-z 0.8 --tau-c 0.8 --dead 0.35"

# landing page
node story-build.cjs build                  # ~75 s take: build-frames/ + build-events.json
node render.cjs build landing-build --speed 1.5 $CALM
node render.cjs build plain --speed 1.5     # no captions, for the poster
ffmpeg -ss 33.6 -i plain.mp4 -frames:v 1 -vf scale=1440:-2 poster.png   # chart with three species

# Examples page
node story-patient.cjs patient
node render.cjs patient clinical-explorer --speed 1.2 --zoom --captions

# webm next to each mp4
ffmpeg -i landing-build.mp4 -c:v libvpx-vp9 -b:v 0 -crf 38 -an landing-build.webm
```

- `film.cjs` drives the browser: fake cursor and click rings on the top page
  (the app sits in ShinyProxy's `iframe#shinyframe`), waits on `shiny:idle`,
  records with CDP `Page.startScreencast`. The screencast sends CSS-pixel frames
  whatever `deviceScaleFactor` says; `--force-device-scale-factor=2` gets 2x frames.
- `story-*.cjs` are the clips. Captions, zoom levels and cuts are logged as
  events, not drawn, so `render.cjs` can produce any style from one take.
  Blocks are appended by dragging from the previous block's rail dot down into
  empty space, which adds and connects in one step.
- `render.cjs` drops `cut-start`/`cut-end` windows, speeds up, runs a camera
  (zoom level from the story, follows the cursor with a dead zone) through
  ffmpeg `sendcmd` + `crop`, and overlays the captions as PNGs. `S.zoom(..., { abs: true })`
  is not toned down by `--zscale` (the close-up on the code at the end).
- In the Report view the ggplot chunk sometimes stays at "waiting for R code"
  until the view is rebuilt. `story-build.cjs` flips Build/Report once and
  marks that stretch as a cut.
